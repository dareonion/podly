# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) and other coding agents when working with code in this repository. `AGENTS.md` is a symlink to this file — edit here only.

## Project

Podly — a native Android podcast player (Kotlin, Jetpack Compose, Media3) with Android Auto and Chromecast support. Two modules: the `app` Android module (package `com.podly`) and a JVM-only `generator` module that pre-computes AI recommendation JSON in CI (published to GitHub Pages at dareonion.github.io/podly; the app just downloads the static files).

## Commands

Gradle needs JDK 21. Machine-specific JDK paths live in `~/.gradle/gradle.properties` (`org.gradle.java.home`) — never in the tracked `gradle.properties`:

- Mac: `export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"` (or set the user-level property once)
- Linux box: already configured (Temurin 21); plain `./gradlew` works

```sh
./gradlew assembleDebug          # build debug APK
./gradlew testDebugUnitTest      # run JVM unit tests
./gradlew testDebugUnitTest --tests "com.podly.RssParserTest"   # single test class
./gradlew :generator:test        # generator module tests
./gradlew lintDebug              # Android Lint (known issues: app/lint-baseline.xml)
adb install -r app/build/outputs/apk/debug/app-debug.apk        # install to device
```

CI: `.github/workflows/android.yml` runs the build, Android Lint (`lintDebug` — pre-existing issues are grandfathered in `app/lint-baseline.xml`, new ones fail), plus all unit tests on every push/PR to main; pushes to main also publish the debug APK to the rolling `latest` GitHub release (stable URL: `releases/latest/download/podly-debug.apk`). `recommendations.yml` regenerates the AI picks JSON weekly (Mondays 08:00 UTC) and deploys it to GitHub Pages.

## Architecture

- **DI**: hand-rolled — `AppGraph` (one instance on `PodlyApp`); access from composables/services via `Context.appGraph`. ViewModels are created with the `appViewModel { ... }` helper in `ui/AppViewModel.kt`. `AppGraph.messages` (`UiMessages`) is an app-wide one-shot snackbar channel rendered by `MainActivity`; `EpisodeActions` reports its failures through it — don't add silent fire-and-forget launches.
- **Data** (`data/`): Room database (`PodlyDatabase`, version 6, `exportSchema = true`) with `podcasts`, `episodes`, `playlists`, `playlist_items`, `listening_segments` tables. "Library" = episodes of subscribed podcasts + individually saved episodes (`inLibrary`). Feed refresh uses conditional GET (per-podcast `etag`/`lastModified`, 304 short-circuits) and runs 4 feeds concurrently; episode rows are upserted via `EpisodeDao.upsertFromFeed` — insert with `OnConflictStrategy.IGNORE` plus a metadata-only UPDATE, so download/progress/library state is never clobbered and `pubDateMs` never churns (undated episodes get a first-seen timestamp). Settings live in Preferences DataStore (`SettingsRepository`).
- **Network** (`network/`): plain OkHttp via the `Http` singleton (no Retrofit); `http://` URLs are retried as `https://` first (Android blocks cleartext, and iTunes still returns http feed URLs). iTunes Search (keyless) for search — pasting a feed URL into Discover search offers it as a direct subscribe result. `RssParser` (XmlPullParser, JVM-testable) for episodes, Apple Marketing Tools JSON for "popular now", PodcastIndex trending (user-supplied key/secret; SHA-1 auth header in `PodcastIndexApi.authHash`). The picks-playlist importer (`PicksImporter`, Settings → Import picks JSON) falls back to the configured episode archives for picks that have rolled off a short feed window, inserting the episode row directly — `ArchiveRescuer` tries Taddy first, then PodcastIndex (whichever has creds), with per-provider in-memory caching. AI recommendations (`network/ai/`) use the official Anthropic Java SDK (`claude-opus-4-8`) or OpenAI via raw HTTP; keys come from Settings. Acclaimed/recent-episode lists come pre-generated from `RemoteRecsApi` + `AiPicksCache` (cached with `generatedAtMs` shown in the UI).
- **Playback** (`playback/`): `PlaybackService` is a Media3 `MediaLibraryService` used by both the in-app UI and Android Auto. The Android Auto browse tree (Continue/Playlists/Library/Downloads) is served from Room in `LibraryCallback`, every list capped at 100. **Key behavior**: `NudgingPlayer` (a `ForwardingPlayer`) remaps `seekToNext()`/`seekToPrevious()` (car/headset buttons) to in-episode nudges, but leaves `seekToNext/PreviousMediaItem` as real queue skips — the in-app skip buttons and Up Next sheet rely on that split. Nudge increments are mutable fields fed live from Settings (no service restart). Queue transitions (skip/jump/auto-advance) restore each episode's saved position; a `pendingResumeEpisodeId` guard stops the 5-second progress saver from clobbering it. Media IDs use the `ep/<id>` / `playlist/<id>` scheme in `MediaIds`. UI talks to the service through `PlayerConnection` (MediaController wrapper exposing a `StateFlow` incl. queue + player error). Streaming is deliberately resilient to dead zones: the load control buffers 5–10 minutes ahead (audio is cheap), and network-flavoured `PlaybackException`s auto-recover in `startNetworkErrorRecovery` — it waits for the OS to report validated internet, then re-prepares (5 attempts, backoff), so a Wi-Fi→cellular handoff no longer strands playback on "press play to retry".
- **Casting** (`playback/`): Chromecast through Media3's `CastPlayer`; the Cast SDK is registered by `CastOptionsProvider` (manifest meta-data, default media receiver). A connected cast session takes over the existing MediaSession via `MediaSession.setPlayer` in `transferPlaybackTo`, which carries queue/index/position/playWhenReady in both directions and rebuilds the items for the destination — so the in-app UI and Android Auto keep driving one session either way. **A Cast device fetches the audio itself and cannot read app-private storage**, so `MediaItemFactory.playable(episode, forCast = true)` always uses the streaming URL (a snackbar says so when the queue held downloads), and every item carries a MIME type because Cast's `DefaultMediaItemConverter` requires one. `progressListener` is a field that moves between players rather than being bound to one, so position saving survives the handover. UI is `CastButton` (a `MediaRouteButton`, invisible until a receiver appears on the network).
- **Downloads** (`downloads/`): WorkManager `CoroutineWorker` streams enclosures to `filesDir/episodes/`; status tracked on the episode row. Policies in Settings: Wi-Fi-only constraint, auto-download N newest per subscribed show, auto-delete played downloads, and auto-download episodes you've started — applied by `Downloader.applyPolicies()` after every refresh. The started-episode policy also fires the moment playback begins (`autoDownloadStartedEpisode` from `PlaybackService`) and is always constrained to unmetered networks regardless of the global Wi-Fi-only setting, since its point is stocking up on Wi-Fi rather than re-fetching over cellular what is already streaming; the sweep covers the last 30 days, capped at 20. `episodes.autoDownloadBlocked` marks manually removed downloads so auto-download won't re-fetch them (cleared by an explicit re-download). Playback prefers the local file (`MediaItemFactory.localUriOrNull`).
- **Streaming cache**: `MediaCache` is a process-wide `SimpleCache` singleton (1 GB LRU in `cacheDir/media`) wrapped around the OkHttp data source in `PlaybackService`; never construct a second instance on the same directory. Downloads (file:// URIs) bypass it.
- **Playlists**: per-playlist `sortMode` (MANUAL / CHRONO_ASC / CHRONO_DESC). Chrono sorts are applied in `PlaylistRepository.applySort`; manual order is `playlist_items.manualPosition`, edited via drag handles (`sh.calvin.reorderable`) only when in MANUAL mode. AI-saved playlists are named with the picks' generation date.

## Conventions

- Kotlin, 4-space indent, trailing commas in multiline declarations. Compose screens are PascalCase (`LibraryScreen`); other classes use descriptive suffixes (`PodcastRepository`, `FeedRefreshWorker`, `PlaybackService`). Prefer the existing `Context.appGraph` / `appViewModel { ... }` helpers over introducing a DI pattern.
- Tests are JVM JUnit under `app/src/test/java/com/podly/` (`*Test.kt`). Keep parsing and business logic JVM-testable; add focused tests for repository sorting, parser changes, auth/header logic, and AI response parsing. Robolectric is available for Android-dependent tests (use `@Config(application = Application::class)` — `PodlyApp.onCreate` starts WorkManager). Run `./gradlew testDebugUnitTest` before submitting changes.
- Commits: short imperative subjects, one behavior change each. PRs: describe the user-visible change, list tests run, call out Android Auto/playback impact, include screenshots for UI changes.
- Never commit secrets or signing material. Release signing is read from `PODLY_RELEASE_*` keys in the untracked `local.properties`; API keys are user settings, not source constants.

## Gotchas

- The Anthropic SDK pulls Apache HttpComponents; the `packaging { resources.excludes }` block in `app/build.gradle.kts` resolves META-INF merge conflicts — keep it.
- `RssParser` deliberately uses `XmlPullParserFactory` (not `android.util.Xml`) so unit tests run on the JVM (kxml2 is a test dependency).
- Room schema export is on: bumping the DB version regenerates `app/schemas/.../<N>.json` on the next build — commit it. Hand-written migration index names must match Room's generated names (`index_<table>_<column>`). `MigrationTest` guards this: it rebuilds a v5 database from the exported schema JSON (read from the repo — AGP doesn't package unit-test assets, so Room's `MigrationTestHelper` can't be used) and migrates it through `PodlyDatabase.build`, which validates the result against the current entities.
- API keys are deliberately stored unencrypted in DataStore (androidx security-crypto is deprecated); the mitigation is the backup rules in `res/xml/` that exclude the settings DataStore and downloaded audio from cloud backups. Keep those rules in sync if DataStore file names change.
- `gradle.properties` is machine-neutral (configuration cache enabled). Don't re-add `org.gradle.java.home` there.
- Sideloaded builds only appear in Android Auto after enabling Developer settings → "Unknown sources" in the Android Auto app on the phone — and Android Auto only re-scans its app list on restart, so force-stop it (or reboot the phone) after toggling or after installing a new app.
- Debug builds must all sign with the same shared debug keystore or `adb install -r` / release-APK updates fail with `INSTALL_FAILED_UPDATE_INCOMPATIBLE`. The canonical `~/.android/debug.keystore` is shared across dev machines, and CI restores it from the `DEBUG_KEYSTORE_B64` repo secret (base64 of the keystore) before building; without the secret CI signs with a throwaway key and the published APK can't update an existing install. GitHub runners set `XDG_CONFIG_HOME`, and AGP looks for its `.android` dir there *before* `~/.android` — the restore step must write both paths or it is silently ignored.
- The cast button has two hard host requirements, each of which crashed at runtime while the app still built and passed tests. (1) `Theme.Podly` must stay **AppCompat-based**: `MediaRouterThemeHelper` reads AppCompat attrs like `colorPrimary` off the *activity's* theme, and on a framework theme they resolve to 0 — the picker then dies with `background can not be translucent: #0`. Theming only the button's context is not enough, because the dialog uses the activity. `Theme.Podly` also carries `mediaRouteButtonStyle`, which AppCompat itself doesn't supply. (2) `MainActivity` must stay a **`FragmentActivity`**: the picker is a `DialogFragment`, and `MediaRouteButton` throws `The activity must be a subclass of FragmentActivity` without a `FragmentManager`.
- `MediaSession`'s getters (including `session.player`) assert the application thread. `LibraryCallback` resolves media items on `Dispatchers.IO`, so anything it needs about the session must come from a plain field — `PlaybackService` mirrors the active player and cast state into `@Volatile` fields for exactly this reason. Reading `session.player` there threw and failed the whole set-media-items operation, which showed up as the player flashing and then starting late.
